# DivalHR French and English Standard

## Policy

French and English are equal, first-class product languages. A feature is incomplete if one language is missing or materially inferior.

## Locale model

- Supported launch locales: `fr` and `en`
- Organization default locale
- User-preferred locale
- Document-template locale
- Notification-template locale
- AI-response locale
- Country-specific date, number, timezone, and currency formatting

Language preference is independent of country and currency.

## Engineering rules

1. No user-facing text is hard-coded in components, APIs, jobs, or database procedures.
2. Translation keys are stable identifiers.
3. APIs return stable codes and values; presentation layers translate labels.
4. Back-end validation returns a machine code plus safe interpolation parameters.
5. Date, time, number, and money formatting uses locale-aware libraries.
6. French text must support accents and Unicode throughout storage, search, export, and PDF generation.
7. Customer-created labels may store both French and English values with a configured fallback.
8. Search supports French diacritics without corrupting exact identifiers.
9. AI prompts and evaluations exist in both languages.
10. Notification templates are versioned and approved separately by locale.

## Translation structure

Example:

```
locales/
  en/
    common.json
    people.json
    operations.json
    payroll.json
    finance.json
  fr/
    common.json
    people.json
    operations.json
    payroll.json
    finance.json
```

## Fallback

1. User locale
2. Organization default locale
3. English internal fallback

A missing translation is logged and fails CI for production keys. Users should never see raw translation keys.

## Required testing

- Translation-key parity
- Long French labels and responsive layout
- Accents in search, import, export, and PDFs
- Locale-specific dates and numbers
- CDF and USD formatting
- French and English email, SMS, WhatsApp, Teams, and Slack templates
- Screen-reader labels in both languages
- AI task performance and safety in both languages

### Invitation emails and pages (MVP-010)

- Invitation emails are versioned templates per locale (`mail/invitation-v1-fr.{txt,html}`, `…-en…`), chosen by the invitation's `locale`, never by the administrator's UI language. Dates are formatted in the organization's time zone with the locale's conventions, and the role is translated.
- The acceptance page uses the invitation's language; the visitor can still switch. The identity provider's password email uses the `locale` attribute set on the new identity.
- Delivery-state wording is fixed in both languages: "Invitation créée – envoi en attente" / "Invitation created – delivery pending" for `QUEUED`, "Invitation envoyée" / "Invitation sent" only for `SENT`, and an actionable warning for `FAILED`.

### Privileged MFA (MVP-011)

- The web app's `MFA_REQUIRED` message and MFA-required page (`mfa.*`) exist in French and English, including lost-device and clock guidance; the retry sign-in passes the current `ui_locales`.
- Keycloak's own code-entry and authenticator-setup pages are used as shipped (keycloak.v2), in French and English. After sign-in they follow the user's `locale` attribute, which invitations set to the invitation's language.
- The realm message `divalhrMfaEnrollmentRequired` (privileged user without an authenticator) is defined in both languages in the realm's localization texts and checked by the realm tests and `pnpm realm:verify`.

### First tenant administrator (MVP-014)

- The platform panel (`firstAdmin.*`), its page and navigation entry ("Premier administrateur" / "First administrator") and the codes `ORGANIZATION_NOT_FOUND` and `TENANT_ADMIN_BOOTSTRAP_UNAVAILABLE` exist in French and English. The invitation language defaults to the organization's default language and the email uses the invitation's language, as in MVP-010.
- Tenant administrators see the origin of a bootstrap invitation: "Invité par DivalHR lors de la création de l’organisation" / "Invited by DivalHR when the organization was set up".

### Membership authority (MVP-012A)

- No new error code: membership denials use the existing `ACCESS_DENIED` text. The session card shows "Aucune organisation" / "No organization" (`session.noTenant`) for a platform administrator without a tenant.

### Access review (MVP-012B)

- Approved French terms (architect decision on #37, A6), with grammatical agreement in sentences: "Revue des accès", "Toute l’organisation", "Hérité de l’organisation" (as "Accès hérité de l’organisation (couvre ce site)" / "(couvre cette entité juridique)"), "Adresse non enregistrée". English: "Access review", "Entire organization", "Inherited from the organization", "Address not recorded".
- Dates use the viewer's device time zone with the visible statement "Dates affichées dans le fuseau horaire de votre appareil." / "Dates shown in your device’s time zone." (R3). Result counts use i18next plural forms.

### Authorization denial audit (MVP-013)

- No user-facing change: no new key, code or template. Denials keep their existing `ACCESS_DENIED`, `TENANT_CONTEXT_MISSING`, `MFA_REQUIRED` and `RATE_LIMITED` French and English texts and the MFA challenge; tests assert the bodies are unchanged. Denial evidence stores only stable server-owned codes.

### Employee import (MVP-020)

- The template exists in French and English (`GET /employee-imports/template?lang=fr|en`). Uploads accept French labels, English labels, the language-neutral column keys, or any mix (`headerLanguage` = `fr`, `en` or `mixed`). Header matching ignores letter case, accents, apostrophe and dash variants and repeated spaces, so "Date d’entrée", "date d'entree" and `start_date` are the same column.
- French spreadsheets usually separate with semicolons and English ones with commas: both are accepted, chosen from the header line. Files must be UTF-8 (Excel: "CSV UTF-8"); a byte-order mark is accepted.
- Dates in files are ISO `YYYY-MM-DD` in both languages, never `JJ/MM/AAAA` or `MM/DD/YYYY`, so the same file means the same dates for everyone. The page displays them in the viewer's language.
- Names keep their accents: values are normalized to NFC and lengths count Unicode code points, so "Élodie" is 6 characters however it was typed.
- The API returns stable row error codes (`ROW_*`), column keys and file-level reasons; the page translates them. French terms: "Matricule", "Prénoms", "Nom de famille", "Date d’entrée", "Importer des employés". Counts use i18next plural forms.

### Employment history (MVP-021)

- Pages "Employés" / "Employees" (directory and search) and the employee record. All labels, statuses, kinds, contract categories, compensation bases, reasons, timings and problem messages exist in French and English; the API returns stable codes only (`AssignmentKind`, `EmploymentChangeReason`, `MANAGER_INVALID` with `params.reason`, `PLACEMENT_INVALID` with `params.field` and `params.reason`, ...).
- Effective dates are calendar dates in the organization's time zone (the business date), not instants: the page formats them as dates without any time-zone conversion, so a change "à partir du 1 novembre 2026" is the same day for every viewer. The page states today's business date.
- Search ignores accents, apostrophes, hyphens and letter case in both languages ("elodie nkanza" finds "Élodie N’Kanza"); queries are normalized to NFC and lengths count code points.
- Contract categories are descriptive ("Durée déterminée" / "Fixed term"), not legal classifications; compensation bases never carry amounts. Counts use i18next plural forms.

### Separation (MVP-022)

- New sections on the employee record: "Sortie" / "Separation" and "Accès à DivalHR" / "DivalHR access", plus an access column in the access review ("Accès DivalHR" / "DivalHR access": "Actif" / "Active", "Accès révoqué" / "Access revoked"). Every reason, timing, state, access state, reminder, status, acknowledgement and problem message exists in both languages; the API returns stable codes only (`SeparationReason`, `SeparationAccessState`, `SEPARATION_PROTECTED` with `params.reason`, `SEPARATION_ACKNOWLEDGEMENT_REQUIRED` with `params.acknowledgement`, counts in `params.count`).
- The last day is a business date formatted without time-zone conversion; the instant access ends is an instant, shown in the viewer's language and device time zone. Counts of direct reports, periods and blockers use i18next plural forms.
- Reason labels are descriptive ("Accord mutuel" / "Mutual agreement"), not legal qualifications of the separation.

### Contracts (MVP-030)

- Pages "Modèles de contrat" / "Contract templates", the "Contrats" / "Contracts" section of the employee record and "Mes contrats" / "My contracts" for employees. Every state, language, field, problem reason, void reason, warning and message exists in both languages; the API returns stable codes only (`ContractState`, `ContractTemplateProblemReason` with a line number, `CONTRACT_VALUE_MISSING` with `params.placeholder`, `CONTRACT_DATES_INVALID` with `params.field`).
- **Single-language contract text (D3).** Each template version, and so each issued contract, is in one language chosen by the administrator. The French and English lines of a template are separate versions, each approved by a person; no machine translation or AI wording. The contract is shown as an article with its own `lang` attribute, while the surrounding interface (including the integrity footer) follows the viewer's language.
- **Rendered values.** Dates in contract text use server-owned month names and patterns (« 1er mars 2026 », "March 1, 2026") independent of the JDK and browser locale data, so the stored text and its digest are stable; contract types use the MVP-021 labels ("Durée indéterminée" / "Permanent").
- **Terminology (A30-3).** The action is « Accuser réception » / "Acknowledge" and the state « Réception confirmée » / "Acknowledged". No label, state, button, message or error may say « Signer », « Contrat signé », « signé(e) », "Sign contract", "Contract signed", "sign" or "signed"; "signature" appears only in the negative disclaimer (« Ce n’est pas une signature électronique. » / "It is not an electronic signature."). A web test and a Core test enforce this on the locale keys, the API descriptions and enums, and the statements.
- **Acknowledgement statement (D16).** Server-owned and versioned in both languages; the employee sees it in the interface language, and the evidence records the language shown. Version 1 is approved provisionally and needs counsel review before production use; changing one character is version 2.

### Contract expirations (MVP-031A)

- Page « Échéances des contrats » / "Contract expirations" and the home card « Contrats à traiter » / "Contracts needing attention". Approved French wording (A31A-6): « Échus », « Dans les 30 prochains jours », « De 31 à 60 jours », « De 61 à 90 jours », « Calcul au {{date}} ({{timezone}}) ». Rows say « Échu depuis N jours » / "Overdue by N days", « Se termine aujourd’hui » / "Ends today" or « Se termine dans N jours » / "Ends in N days" (plurals).
- The business date, day counts and categories come from the server; the browser only formats the date (as a UTC calendar date, so it never shifts).
- `employees.employmentStatus.ENDED` reads « Emploi terminé » (was « Contrat terminé »): an ended employment is not an ended contract.

### Product shell and role homes (UI-001)

- Navigation labels keep their existing keys and wording. New groups: "Vue d’ensemble" / "Overview", "Plateforme" / "Platform", "Personnel" / "People", "Organisation" / "Organization", "Documents", "Accès et sécurité" / "Access and security", "Mon espace" / "My space".
- Shell terms: "Espace de travail" / "Workspace", "Votre organisation" / "Your organization", "Plateforme DivalHR" / "DivalHR platform", "Menu du compte" / "Account menu", "Identifiant de l’organisation" / "Organization ID", "Réduire le menu" / "Collapse navigation", "Développer le menu" / "Expand navigation", "Ouvrir le menu" / "Open navigation", "Fermer le menu" / "Close navigation", "Fil d’Ariane" / "Breadcrumb".
- Environment badge (UI1-2): "Environnement de développement" / "Development environment", "Environnement de test" / "Test environment", "Environnement de préproduction" / "Staging environment"; production shows none. The label is chosen from the allow-listed runtime value through fixed keys, never from configuration text. It never claims that the data is test data.
- Planned modules are labelled « À venir » / "Coming later" with the sentence « Prévu dans la feuille de route DivalHR. Pas encore disponible. » / "On the DivalHR roadmap. Not available yet." They are text only, with no date.
- Long French labels wrap rather than truncate in the sidebar, on cards and on buttons. Narrow screens show "FR" / "EN" while each button's accessible name stays « Français » / "English".

### Public landing page (UI-002)

- All copy is under `landing.*` in both locale files; brand and integration names (M-PESA, QuickBooks, Microsoft Teams…) are not translated, and carry `lang="en"`. Standards and methods are localized: "Bank transfer" / « Virement bancaire », "REST API" / « API REST ».
- Availability labels: "Available now" / « Disponible » and "Coming later" / « À venir »; integrations: "Planned" / « Prévu ».
- Legal wording approved for the test release, subject to business and legal review before production (UI2-5): the payment-responsibility note (`landing.payroll.note`), the integration disclaimer (`landing.integrations.note`) and the finance sentence "DivalHR does not make lending decisions." / « DivalHR ne prend aucune décision de crédit. ». Their meaning must not change without that review.
- The page explains no authentication mechanics: "Already a customer? Sign in securely." / « Déjà client ? Connectez-vous en toute sécurité. » (UI2-3).
- The demo request opens `mailto:contact@dival.ai` with a localized subject only: "DivalHR demo request" / « Demande de démo DivalHR ».
- The document title follows the language: `landing.documentTitle`.

## Content ownership

Product owns terminology. Engineering owns extraction and validation. A qualified bilingual reviewer approves critical HR, payroll, privacy, and financial language.
